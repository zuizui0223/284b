# Product-B Level-C set-valued dependency v2

## Why this design exists

The finite Level-C v1 admission screen is closed. It screened the predeclared maximum of 12 external biological systems and admitted none. Eleven stopped at the event-relation gate because the proposed hard statement required one named partner or host even when the biology allowed multiple functionally valid alternatives; SMIL001 stopped later at operational-space and focal-evidence-independence gates.

That result is retained exactly as a v1 structural admission outcome. v2 does **not** reopen, rescue, rerank, or replace any v1 candidate.

The narrow design lesson is that a directional biological dependency can be set-valued.

## Relation

For one prospectively frozen event key `k`, let:

- `E(k)` be the dependent biological event;
- `R(k)` be the externally frozen set of biologically admissible required alternatives;
- `S_r(k)` be the adequate required-role support answer for member `r`.

The v2 hard relation is:

`E(k) -> OR_{r in R(k)} S_r(k)`

Examples of the *form* include reproduction that can be serviced by any member of a closed pollinator set, or larval development that can use any member of a closed host set. These are logical examples only, not empirical authorizations.

## Positive and negative evidence are asymmetric

If `E(k)` is positively established and any frozen member has adequate positive support, the OR relation has a positive witness and the key is consistent. Unknown answers for other members do not erase that witness.

The converse is harder. If every represented member is adequately negative, the key is a hard violation **only if the membership set itself is externally certified complete**. When set completeness is unresolved, the key remains unresolved because an unrepresented alternative may satisfy the dependency.

Thus:

- one positive frozen alternative can establish consistency;
- all known negatives do not establish violation unless the alternative universe is closed.

`absence of a reported alternative` is never treated as proof that the set is complete.

## Why set membership must be frozen

Set membership is part of the scientific hypothesis, not bookkeeping. If a key with one negative required member is classified as violated, then adding a second positive member after seeing the result can convert it to consistent.

Therefore v2 forbids after focal outcome access:

- adding members;
- removing members;
- redefining membership from occurrence overlap;
- redefining membership from fitted role surfaces;
- redefining membership from the cross-role result itself.

A set-completeness claim also requires external evidence independent of the focal relation outcome.

## Event and answer boundaries remain unchanged

Set-valued dependency does not make generic occurrence surfaces into biological event answers. Each member must still have an answer that matches the required event-level estimand, and the dependent role must independently measure its event.

Missing or inadequate answers remain unresolved. A failed member model is not encoded as member absence.

The same-target Level-A q95 remains inapplicable as a universal cross-role tolerance.

## Freshness boundary

Because v2 is motivated after seeing the v1 screen, it must not circumvent that finite screen by repackaging known candidates under a more permissive relation.

Accordingly, the v2 confirmatory candidate pool excludes:

- all 12 v1 screened candidates; and
- the post-cap *Ganaspis kimorum* -> *Drosophila suzukii* system that was noticed only after the v1 hard stop.

This exclusion is methodological, not a judgment that those systems are biologically uninteresting.

A future v2 candidate search requires its own prospective finite-search protocol and a fresh candidate pool. No such search is authorized by the current v2 design.

## Current boundary

Allowed now:

- pure set-valued classifier functions;
- synthetic tests;
- formal analysis of completeness and monotonicity;
- drafting a future response-blind v2 admission protocol.

Not allowed now:

- new candidate search;
- occurrence/source feasibility;
- focal role-answer construction;
- hard invariant opening;
- soft cross-check opening;
- process knockout.

This design adds no empirical endpoint. The 284b empirical ledger remains **1**.
